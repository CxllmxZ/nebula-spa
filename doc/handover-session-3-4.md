## Problems Encountered + Fixes (Chronological)

### Session 3 — Cloudflare + D1 Setup

#### 1. `CLOUDFLARE_ACCOUNT_ID` placeholder ค้างใน shell env

**Symptom:** `wrangler d1 create` fail with URL containing `your_account_id_from_dashboard_sidebar`

**Root cause:** `.env.example` มี placeholder text ที่ shell auto-load เข้า env vars

**Fix:**
```powershell
Remove-Item Env:CLOUDFLARE_ACCOUNT_ID
```
Long-term: `.env.example` ควรเก็บ placeholder ที่ **ไม่ conflict** กับชื่อ env var (หรือ comment out ตัวที่ยังไม่มีค่า)

---

#### 2. `dotenv/config` โหลด `.env.local` ไม่ได้

**Symptom:** Drizzle Kit error `accountId: undefined, databaseId: undefined, token: undefined`

**Root cause:** `import 'dotenv/config'` default โหลด `.env` เท่านั้น — `.env.local` เป็น Next.js convention ไม่ใช่ dotenv default

**Fix:** เปลี่ยน import pattern ใน `drizzle.config.ts`:
```typescript
import { config } from "dotenv";
config({ path: ".env.local" });
```

---

#### 3. Drizzle config type import ผิด

**Symptom:** TypeScript error + wrong `satisfies` type

**Root cause:** เขียน `import type { defineConfig }` (type-only) แต่ `defineConfig` เป็น **function** ไม่ใช่ type

**Fix:** ใช้ `defineConfig()` pattern (runtime function):
```typescript
import { defineConfig } from "drizzle-kit";
export default defineConfig({ ... });
```

---

#### 4. Windows symlink permission (`EPERM`)

**Symptom:** OpenNext build fail with `EPERM: operation not permitted, symlink`

**Root cause:** Windows default ไม่ให้ non-admin user สร้าง symlinks (OpenNext ต้องการสำหรับ sharp image optimizer)

**Fix:** 2 tions:
- **A:** Enable Developer Mode (Settings → System → For developers)
- **B:** Run PowerShell as Administrator (temporary)

Long-term: Developer Mode = one-time setting, ปลอดภัย

---

#### 5. pnpm symlink incompat กับ OpenNext bundler

**Symptom:** Runtime error `Dynamic require of "/.next/server/middleware-manifest.json" is not supported`

**Root cause:** pnpm ใช้ symlink-based `node_modules` — OpenNext bundler resolve symlinks ไม่ถูก

**Fix:** เพิ่ม `.npmrc`:
```
shamefully-hoist=true
node-linker=hoisted
```

จากนั้น:
```powershell
Remove-Item -Recurse -Force node_modules
Remove-Item pnpm-lock.yaml
pnpm install
```

Reference: [Cloudflare workers-sdk #10236](https://github.com/cloudflare/workers-sdk/issues/10236)

---

#### 6. Missing `NextResponse` import in smoke test route

**Symptom:** `TypeError: Cannot read properties of undefined (reading 'default') at interopDefault`

**Root cause:** Route file ใช้ `NextResponse.json(...)` แต่ไม่ได้ import → module fail to load → Next.js interopDefault ได้ undefined

**Fix:** เพิ่ม `import { NextResponse } from "next/server";`

**Lesson:** TypeScript อาจไม่ catch ในบาง config — always double-check imports

---

#### 7. `runtime = "edge"` conflict กับ @opennextjs/cloudflare

**Symptom:** Build warning + route crash

**Root cause:** `runtime = "edge"` เป็น Vercel-specific pattern — @opennextjs/cloudflare ใช้ Node.js runtime (compat mode) + `nodejs_compat` flag แล้ว

**Fix:** ลบบรรทัด `export const runtime = "edge";` ออกจาก route handlers

---

#### 8. Wrangler binding name confusion

**Symptom:** ผมแนะนำ `env.DB` แต่ user config ไว้เป็น `env.nebula_spa_db`

**Root cause:** ผม assume convention ("มักจะเป็น DB") — จริงๆ binding name ใน `wrangler.toml` เป็น source of truth

**Fix:** ยึด `wrangler.toml` เสมอ — check ก่อน suggest

**Lesson:** อย่า assume convention เมื่อ user setup ต่างจาก template

### Session 4B — Auth API + Middleware

#### 12. Next.js 16 `proxy.ts` + @opennextjs/cloudflare = Incompatible

**Symptom:** Build error `Node.js middleware is not currently supported. Consider switching to Edge Middleware.`

**Root cause:** Next.js 16 rename `middleware.ts → proxy.ts` **บังคับ Node.js runtime** (ไม่ให้เลือก edge) — แต่ @opennextjs/cloudflare **ยังไม่ support Node.js middleware**

**Fix:** ใช้ deprecated `middleware.ts` convention (ยังทำงาน + edge runtime):
```powershell
Move-Item src/proxy.ts src/middleware.ts
```

แก้ function name `proxy` → `middleware`

**Trade-off ที่รับ:**
- Warning `middleware.ts is deprecated` ตอน build (ignore)
- ต้อง migrate กลับ `proxy.ts` วันหลังตอน OpenNext support

Reference: [Cloudflare workers-sdk #13755](https://github.com/cloudflare/workers-sdk/issues/13755)

---

#### 13. Better Auth `MISSING_OR_NULL_ORIGIN` error

**Symptom:** POST signup return `{"code": "MISSING_OR_NULL_ORIGIN"}`

**Root cause:** Better Auth CSRF protection require `Origin` header — Postman default ไม่ส่ง

**Fix:** เพิ่ม `trustedOrigins` ใน `src/lib/auth.ts`:
```typescript
return betterAuth({
  baseURL,
  trustedOrigins: [
    "http://localhost:8787",
    "http://localhost:3000",
  ],
  ...
});
```

**Lesson:** Production ก็ต้องมี trustedOrigins อยู่แล้ว — fix ล่วงหน้าไม่เสีย

---

#### 14. Postman cookie state ค้างระหว่าง signup requests

**Symptom:** Signup admin ผ่าน แต่ signup staff request ที่ 2 fail

**Root cause:** Better Auth `autoSignIn: true` set session cookie หลัง signup → Postman เก็บใน cookie jar → ส่งไปกับ request ที่ 2 → conflict state

**Fix:** Clear Postman cookies ก่อนทุก signup:
- Postman → Cookies button → localhost:8787 → Remove all
- **หรือ** ปิด Postman เปิดใหม่

**Lesson:** เจอเฉพาะตอน test — real browser flow ไม่เจอ (user login แล้วอยู่นาน + logout ก่อน signup อีกคน)

---

#### 15. Worker.js LastWriteTime แสดงเวลาเก่า (false alarm)

**Symptom:** ตรวจ `(Get-Item .open-next/worker.js).LastWriteTime` แสดง July 23 (Session 3) แม้ build ใหม่วันนี้

**Root cause:** ผมสรุปเร็วว่า build ไม่ทำงาน — จริงๆ **`worker.js` (2.22KB) = thin entry point** ที่ dynamic import `.open-next/server-functions/default/handler.mjs`

Actual Next.js code อยู่ใน `handler.mjs` — ตรวจตัวนั้นแทน

**Lesson:** เช็ค file size ก่อนสรุป — worker.js เล็กกว่า 1MB = แน่นอนไม่ใช่ bundle full

---

#### 16. Admin pages เป็น static → middleware bypass

**Symptom:** Middleware ไม่ intercept `/admin` → return 200 OK แทน 307 redirect

**Root cause:** Admin pages เป็น placeholder ไม่มี data fetching → Next.js prerender เป็น **static** → served ผ่าน `[assets]` binding โดยตรง → **bypass middleware** (middleware run เฉพาะ dynamic routes)

**Fix:** Force dynamic ที่ `src/app/admin/layout.tsx`:
```typescript
export const dynamic = "force-dynamic";
```

**Verify:** Build log route table ควรแสดง `ƒ /admin` (dynamic) ไม่ใช่ `○ /admin` (static)

**Trade-off:** Login page ก็ dynamic → เสีย prerender advantage เล็กน้อย (Cloudflare Workers ~5ms cold start = acceptable)

---

#### 17. Matcher negative lookahead `((?!login).*)` ไม่ parse

**Symptom:** Middleware set matcher `/admin/((?!login).*)` แต่ไม่ intercept

**Root cause:** Next 16 / OpenNext parse negative lookahead ไม่ถูก — matcher fail silently → middleware ไม่ run

**Fix:** ใช้ simple matcher + check in code:
```typescript
export function middleware(request: NextRequest) {
  const pathname = request.nextUrl.pathname;
  if (pathname === "/admin/login") {
    return NextResponse.next();
  }
  // ... rest of logic
}

export const config = {
  matcher: ["/admin/:path*"],
};
```

**Lesson:** Next.js matcher = keep simple, ใช้ regex tricks ตรงไหนก็ pain — code check ชัดเจนกว่า

## Gotchas Summary (สำหรับ Session 5+)

### Windows-specific

1. **PowerShell curl = Invoke-WebRequest alias** — ใช้ Postman หรือ Git Bash แทน
2. **Enable Developer Mode** สำหรับ symlink permission
3. **PowerShell UTF-8 display bug** — Thai chars แสดง `à¸—à¸¸` แต่ไฟล์จริง UTF-8 ok
4. **Wrangler dev hold file lock** — Ctrl+C **ก่อน** rebuild เสมอ

### Build workflow

5. **`wrangler dev` ต้อง build ก่อน** — `opennextjs-cloudflare build` แล้วค่อย `wrangler dev`
6. **Build cache aggressive** — ต้อง `Remove-Item -Recurse -Force .next .open-next` ก่อน rebuild เมื่อเปลี่ยน config
7. **Route ที่ query D1 ต้องใช้ wrangler dev** — `pnpm dev` (Next.js dev) ไม่มี D1 binding

### Next.js 16 + OpenNext

8. **`middleware.ts` (deprecated) — เลี่ยง `proxy.ts`** จนกว่า OpenNext support Node.js middleware
9. **Admin/protected pages ต้อง `force-dynamic`** — ไม่งั้น static prerender bypass middleware
10. **Matcher regex — keep simple** — negative lookahead parse ไม่ได้
11. **Route handlers ห้ามใส่ `runtime = "edge"`** — @opennextjs/cloudflare ใช้ Node.js runtime

### Better Auth

12. **Postman cookie state ค้าง** — clear ก่อนทุก signup/login test
13. **trustedOrigins ต้อง config** — production URL เพิ่มตอน deploy
14. **`@better-auth/cli` ใช้ `pnpm dlx`** ไม่ install local
15. **Signup CLI generate schema ต้อง export `auth`** — dual-mode pattern (CLI + runtime)

### Drizzle Kit

16. **`dotenv` ต้อง config path `.env.local`** — default โหลด `.env` เท่านั้น
17. **Migration apply order:** generate → apply local → apply remote
18. **Schema merge:** `export * from "./auth.schema"` ใน main `schema.ts`

### Miscellaneous

19. **`env.DB` vs `env.nebula_spa_db`** — check `wrangler.toml` binding name (source of truth)
20. **Session accumulation ปกติ** — 1 login = 1 session, ไม่ auto-cleanup
21. **`worker.js` (2.22KB) = thin wrapper** — actual code ที่ `.open-next/server-functions/default/handler.mjs`
